# 开发与测试

## 连接流程

```text
二维码 / 图片 → 房间与 Renderer 地址
             → 用户确认官方授权（本程序不检查微信登录）
             → 系统路由确定本机 IPv4
             → 读取并确认真实 MediaRenderer 描述
             → SetDeviceAuthorization Enable=1
             → 标准 SSDP 公告 → 投屏应用直接连接真实设备
```

设备地址、端口、Token 和房名来自当前二维码，不按网段或房号推算。描述中的服务地址按相对路径或 URLBase 解析；携带 Token 的登记请求不跟随重定向，也不发送到描述之外的其他源。

`ConnectionServices.cs` 负责登记，`MainViewModel` 负责会话和界面衔接，`SsdpBridge` 只负责公告，不代理设备控制。正式启动使用真实服务；Debug 的「演示房间 / 连接成功」才会切换为明显标注的 Mock。

## 公告和离线

公告从访问当前 Renderer 的本机路由地址发送，使用临时源端口，目标为 `239.255.255.250:1900`，TTL 2。不会枚举网段扫描，也不会关闭或占用 Windows SSDP 服务。

首次发送 3 轮，每轮间隔 300ms，此后每 20 秒发送一轮；缓存有效期 60 秒。身份来自真实描述，根设备、UDN、设备类型与服务分别生成匹配的 NT / USN。`LOCATION` 始终指向真实描述地址，不指向 Helper。

健康检查每 20 秒一次，要求 HTTP 200、合法 MediaRenderer 描述及相同 UDN。第一次失败进入可疑状态，每隔 1 秒重试，连续 5 次失败才下线；其中任意一次恢复就回到正常间隔。每次 HTTP 请求有独立的 5 秒超时。

连接时在登记前后各确认一次描述及设备身份，之后才发布；探活不会在刚连接完成时额外重复下载。

确认离线、路由源地址变化、手动断开或退出时，先停止公告并发送 byebye，再尽力用**原登记 IP**撤销登记。网络已断开时无法保证房台收到清理请求，因此使用短期公告缓存。异常崩溃也只能等待缓存过期。

这一版仅发送标准组播公告，不接收定向 NOTIFY，也没有 M-SEARCH responder、本地 Shadow Renderer、SOAP 或媒体代理。Windows 是否收录公告需要现场验证，不由“发送成功”推断。

## 本地回归

```powershell
dotnet run --project tests/PureKBridge.Tests -c Debug -p:Platform=x64
```

涵盖图片解码、二维码解析、状态切换、取消连接、真实 HTTP/SOAP 请求、协议错误、身份校验、公告格式、路由切换、短暂掉线及退出清理。默认回归不发组播。

## 实际网络验证

先确认要测试的本机 LAN IPv4。网络测试必须显式指定地址，避免测试设备发到 VPN 或虚拟网卡。

```powershell
dotnet run --project tests/PureKBridge.Tests -c Debug -p:Platform=x64 -- --network-smoke --bind <本机LAN地址>
```

该命令启动一个短期 Fake Renderer，用真实连接服务登记和发送组播，同时通过 Windows 原生异步 UPnP Finder 观察测试 UDN。结果写入忽略的 `artifacts/tests/network-smoke.json`。结束时停止公告、撤销登记并关闭 HTTP 服务。成功发送 UDP 不等于 Windows 已发现设备，报告分别记录二者。

Fake Renderer 会在本机提供测试 HTTP 服务，Windows 可能弹出防火墙授权。是否允许由操作者决定；不要自动修改系统设置。未完成此授权时，原生发现测试失败不能据此判定真实房台的兼容性。

若要手动测试完整 GUI：

```powershell
dotnet run --project tests/PureKBridge.Tests -c Debug -p:Platform=x64 -- --serve-fake --bind <本机LAN地址>
```

然后启动 App，导入 `artifacts/tests/network-room.png`。这是假设备，不需要登录微信，直接点击确认继续即可测试登记和发布。该服务仅响应本地测试协议，不控制任何房台；终端按回车关闭，最长运行 10 分钟。

## 参考

- [UPnP Device Architecture](https://upnp.org/specs/arch/UPnP-arch-DeviceArchitecture-v1.1.pdf)：设备身份与 SSDP 公告格式。本项目发送兼容 UPnP 1.0 的公告，不编造真实设备的 BOOTID / CONFIGID。
- [Windows UPnP 异步发现](https://learn.microsoft.com/en-us/windows/win32/api/upnp/nf-upnp-iupnpdevicefinder-createasyncfind)：网络测试观察器使用此接口；它不属于 Helper 的发布逻辑。
